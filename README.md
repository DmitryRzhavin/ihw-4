# ИДЗ №4 АКОС — вариант 32 «Кухня ресторана»

Сетевое консольное приложение на C11 для Linux. Кухня ресторана работает как
TCP-сервер, а посетители, официанты и повара подключаются к ней отдельными
клиентами. Для наблюдения за всей системой используется отдельная программа-наблюдатель.

В ИДЗ №1 кухня моделировалась последовательно, в ИДЗ №2 — потоками,
в ИДЗ №3 — процессами с POSIX IPC. Здесь предметная модель, формат меню
и конфигурации сохранены, а взаимодействие вынесено на TCP. Семафоры и общая
память не используются: состояние кухни хранится только на сервере.

## Программы

| Программа | Назначение |
|---|---|
| `kitchen_server` | Кухня, очереди, оборудование, проверка инвариантов, журнал |
| `kitchen_client` | Один участник: `visitor`, `waiter` или `cook` |
| `kitchen_observer` | Наблюдатель: общий поток событий и строка состояния |

Клиент показывает только то, что получил от сервера. Наблюдатель показывает
события всей кухни. Подключать можно любое число наблюдателей (до лимита соединений).

## Сборка

Нужны GCC и CMake (без CMake `build.sh` соберёт проект напрямую GCC).

```bash
bash scripts/build.sh
```

Получаются `build/kitchen_server`, `build/kitchen_client`, `build/kitchen_observer`
и тест ядра `build/model_test`.

## Запуск на одном компьютере

Нужно четыре терминала в каталоге проекта.

Сервер:

```bash
./build/kitchen_server --port 5320 --unit-ms 150 --config configs/demo.conf
```

Наблюдатель:

```bash
./build/kitchen_observer --port 5320 --name obs1
```

Клиенты (4 посетителя, 2 официанта, 3 повара — как в `demo.conf`):

```bash
for i in 1 2 3 4; do ./build/kitchen_client --port 5320 --role visitor --id $i & done
for i in 1 2; do ./build/kitchen_client --port 5320 --role waiter --id $i & done
for i in 1 2 3; do ./build/kitchen_client --port 5320 --role cook --id $i & done
wait
```

Номера клиентов начинаются с 1. Число клиентов каждой роли должно совпадать
с `visitors`, `waiters` и `cooks` в конфигурации. Клиенты и наблюдатели можно запускать
раньше сервера: они повторяют подключение до `--connect-timeout` (по умолчанию 3000 мс).

## Работа в сети

Адрес и порт всегда задаются в командной строке. По умолчанию сервер слушает
только `127.0.0.1`. Для приёма соединений с других компьютеров:

```bash
./build/kitchen_server --host 0.0.0.0 --port 5320
```

Клиенты и наблюдатели подключаются командой с `--host АДРЕС_СЕРВЕРА`. Поддерживается только IPv4.
Аутентификации и шифрования нет, поэтому сеть должна быть доверенной.
В поставленной проверке сетевой режим на нескольких компьютерах не запускался:
проверено только подключение через `localhost`.

## Подключение и отключение на ходу

Наблюдателя можно остановить `Ctrl+C` и запустить снова: сервер продолжит работу,
а новый наблюдатель получит последние 100 событий и дальше видит поток.

Клиентов также можно отключать (`Ctrl+C`) и запускать заново с тем же номером:

- повар теряет текущую операцию: она возвращается в очередь (`ABORT`), оборудование освобождается;
- официант оставляет заказ без исполнителя (`ORPHAN`), его подхватывает другой или вернувшийся официант (`ADOPT`);
- заказ не выдаётся посетителю, пока тот отключён, и выдаётся после его возвращения;
- номер уже подключённого клиента повторно занять нельзя.

Пример для повара, пока идёт прогон:

```bash
pkill -INT -f 'kitchen_client --port 5320 --role cook --id 1'
./build/kitchen_client --port 5320 --role cook --id 1
```

При штатном завершении или остановке сервера все подключённые клиенты и наблюдатели
получают сообщение и завершаются сами.

## Параметры

Сервер: `--host`, `--port`, `--config`, `--unit-ms`, `--timeout`, `--log`, `--no-log`, `--help`.
По умолчанию порт 5320, предел работы 300 с, журнал `kitchen.log` (открывается на добавление).
Клиент: `--role`, `--id`, `--host`, `--port`, `--connect-timeout`.
Наблюдатель: `--host`, `--port`, `--name`, `--connect-timeout`.

Число посетителей задаётся ключом `visitors` в конфигурации. Место обработки отмечено
комментарием в `src/config.c`. Бесконечного режима приёма нет.

Формат конфигурации прежний (см. ИДЗ №3): число официантов и поваров, меню
`dish=Soup|stove:3,table:1`, оборудование, заказы `order=...` либо генерация по
`seed` и `dishes_per_order`, интервалы прихода, вместимость двух очередей, приоритет `fifo`/`lifo`.
`unit_ms` или `--unit-ms` задаёт реальную длительность одной единицы времени.

## Коды завершения

| Код | Смысл |
|---|---|
| 0 | штатное завершение |
| 1 | сервер: занят порт, тайм-аут или нарушение инварианта; клиент: сервер отклонил номер |
| 2 | ошибка аргументов или конфигурации |
| 3 | клиент и наблюдатель: нет сервера либо соединение потеряно |
| 130, 143 | прерывание `SIGINT`, `SIGTERM` |

## Проверки

```bash
bash scripts/run_tests.sh
```

Скрипт запускает тест ядра, сценарии конфигураций, отключения и повторные подключения,
остановку и аварию сервера, неверные данные и ошибки запуска. Всего 19 проверок.
Нужны только Bash, GCC и стандартные утилиты. Проверка журнала выполняется `scripts/check_log.sh`.
Тесты используют случайные порты 20000–40000 и запускаются только по команде.

Если нужен только тест ядра: `./build/model_test`.

## Ограничения

- Сервер однопоточный, опрос сокетов каждые 5 мс; клиенты опрашивают сервер примерно раз в 3 мс.
- Только IPv4, текстовый протокол, без шифрования и авторизации.
- До 256 одновременных соединений; медленный наблюдатель с переполненным буфером отключается.
- Потерю соединения без закрытия сокета (отключение сети, остановка машины) сервер сразу не обнаруживает: TCP keepalive не включён.
- Если посетитель не вернулся после отключения, его заказ остаётся невыданным до тайм-аута сервера.
- Одинаковый `seed` воспроизводит состав заказов, но не порядок событий.
